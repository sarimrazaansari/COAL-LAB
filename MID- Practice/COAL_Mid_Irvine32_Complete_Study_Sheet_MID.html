02 · What Is Assembly?

Assembly language is a low-level language that is much closer to the CPU's actual operations than C/C++.

C++ idea

int x = 10;
int y = 20;
int z = x + y;

Assembly idea

mov eax, 10
mov ebx, 20
add eax, ebx

Afterward, EAX = 30.

Core idea: Assembly means giving very specific instructions to the CPU, using registers and memory.

04 · Registers

Registers are tiny, extremely fast storage locations inside the CPU.

RegisterCommon beginner use
EAXArithmetic, return values, Irvine32 integer input/output.
EBXGeneral-purpose storage.
ECXLoop counter, especially with LOOP.
EDXGeneral-purpose; Irvine32 uses it for the address passed to WriteString.
ESICommonly used as an array/memory pointer.
EDICommonly used as another pointer/index register.
EBPBase/frame pointer; more relevant when procedures/stack frames are studied.
ESPStack pointer.

Register sizes

A 32-bit general-purpose register can be divided into smaller pieces. For EAX:

EAX
 └── AX       (lower 16 bits)
      ├── AH  (upper 8 bits of AX)
      └── AL  (lower 8 bits of AX)

For the current material, focus mainly on the 32-bit registers such as EAX, EBX, ECX, EDX, ESI and EDI.

Exam habit: Whenever tracing code, make a small table of register values after every instruction that changes one.

07 · Strings

A string is a sequence of characters. With Irvine32, a null-terminated string is commonly defined like this:

.data
msg BYTE "Hello World",0

The memory conceptually contains:

H e l l o   W o r l d \0

The final 0 is the null terminator.

OFFSET and strings

mov edx, OFFSET msg
call WriteString

This does not put the characters themselves in EDX. It puts the address of the string in EDX. Irvine32's WriteString then uses that address.

Common confusion: OFFSET msg = address of msg. msg = value stored at msg when used as a memory operand.

09 · Input: Integer, String & Character

Irvine32 provides different input procedures for different kinds of values. The key distinction is that ReadInt/ReadDec/ReadHex return a value in EAX, ReadChar returns a character in AL, and ReadString stores text in a buffer.

Remember: ReadInt → EAX · ReadDec → EAX · ReadHex → EAX · ReadChar → AL · ReadString → EDX = buffer, ECX = size, EAX = character count
InputProcedureRegisters / result
Signed decimal integerReadIntEAX = integer typed
Unsigned decimal integerReadDecEAX = unsigned integer typed
Hexadecimal integerReadHexEAX = value typed
StringReadStringEDX = buffer address, ECX = buffer size, EAX = characters read
Single characterReadCharAL = character typed; key is not echoed

1. Read an Integer — ReadInt

INCLUDE Irvine32.inc

.data
    prompt BYTE "Enter an integer: ",0

.code
main PROC
    mov edx, OFFSET prompt
    call WriteString

    call ReadInt          ; EAX = integer entered
    call WriteInt         ; prints EAX
    call Crlf

    exit
main ENDP
END main
Pattern: call ReadInt → EAX contains the signed decimal integer. If you need to keep it, save it: mov age, eax.

2. Read an Unsigned Decimal Integer — ReadDec

mov edx, OFFSET prompt
call WriteString

call ReadDec          ; EAX = unsigned decimal value
call WriteDec
call Crlf

Use ReadDec when the input is an unsigned 32-bit decimal integer.

3. Read a Hexadecimal Value — ReadHex

mov edx, OFFSET prompt
call WriteString

call ReadHex          ; EAX = hexadecimal value
call WriteHex
call Crlf

The value entered is returned in EAX and can then be displayed with WriteHex.

4. Read a String — ReadString

INCLUDE Irvine32.inc

.data
    prompt   BYTE "Enter your name: ",0
    userName BYTE 31 DUP(0)     ; up to 30 characters + null

.code
main PROC
    mov edx, OFFSET prompt
    call WriteString

    mov edx, OFFSET userName    ; address where text will be stored
    mov ecx, SIZEOF userName    ; buffer size
    call ReadString             ; EAX = number of characters read

    call Crlf
    mov edx, OFFSET userName
    call WriteString
    call Crlf

    exit
main ENDP
END main
RegisterWhat it means for ReadString
EDXAddress of the buffer where the typed string will be stored.
ECXSize of the buffer.
EAXNumber of characters read.
String-input pattern:
mov edx, OFFSET buffer
mov ecx, SIZEOF buffer
call ReadString

The Lab 06 manual uses BYTE 31 DUP(0) for a buffer that can hold up to 30 characters plus the null terminator. ReadString writes a null byte after the entered text, so the buffer can be printed with WriteString.

5. Read a Single Character — ReadChar

INCLUDE Irvine32.inc

.data
    prompt BYTE "Press a key: ",0

.code
main PROC
    mov edx, OFFSET prompt
    call WriteString

    call ReadChar         ; AL = character typed
    call Crlf

    call WriteChar        ; display AL
    call Crlf

    exit
main ENDP
END main
Important: ReadChar does not echo the key. If you want to display it, use WriteChar. To preserve the character, save AL, for example mov bl, al.

6. Complete Example — String + Integer + Character

This combines the three main input types in the same pattern used by the Lab 06 manual.

INCLUDE Irvine32.inc

.data
    pName    BYTE "Enter your name : ",0
    pAge     BYTE "Enter your age : ",0
    pKey     BYTE "Press any key : ",0
    mHello   BYTE "Hello, ",0
    mNext    BYTE "Next year you will be ",0
    mKey     BYTE "You pressed : ",0

    userName BYTE 31 DUP(0)
    age      DWORD ?

.code
main PROC
    ; ----- string -----
    mov edx, OFFSET pName
    call WriteString
    mov edx, OFFSET userName
    mov ecx, SIZEOF userName
    call ReadString

    ; ----- integer -----
    mov edx, OFFSET pAge
    call WriteString
    call ReadInt
    mov age, eax

    ; ----- character -----
    mov edx, OFFSET pKey
    call WriteString
    call ReadChar
    call Crlf
    mov bl, al

    ; ----- display results -----
    call Crlf
    mov edx, OFFSET mHello
    call WriteString
    mov edx, OFFSET userName
    call WriteString
    call Crlf

    mov edx, OFFSET mNext
    call WriteString
    mov eax, age
    inc eax
    call WriteDec
    call Crlf

    mov edx, OFFSET mKey
    call WriteString
    mov al, bl
    call WriteChar
    call Crlf

    exit
main ENDP
END main

Dry run

StepInstructionResult
1mov edx, OFFSET userNameEDX points to the string buffer.
2mov ecx, SIZEOF userNameECX contains the buffer size.
3call ReadStringText goes into the buffer; EAX gets character count.
4call ReadIntEAX gets the entered age.
5mov age, eaxAge is saved in memory.
6call ReadCharAL gets the pressed key.
7mov bl, alThe key is preserved in BL.

10 · Data Transfer Instructions

MOV

mov destination, source

Example:

mov eax, 10
mov ebx, eax

Result:

EAX = 10
EBX = 10

MOV copies; it does not remove the source value.

Memory-to-memory warning

For ordinary MOV usage, you generally cannot directly copy one memory variable to another:

; Not valid as a normal memory-to-memory MOV:
mov num1, num2

Use a register in between:

mov eax, num2
mov num1, eax

XCHG

mov eax, 10
mov ebx, 20
xchg eax, ebx

Afterward:

EAX = 20
EBX = 10

MOVZX

Move with Zero Extension: extra upper bits are filled with zero.

mov al, 5
movzx eax, al

Conceptually: EAX becomes 00000005h.

MOVSX

Move with Sign Extension: preserves the sign when a smaller signed value is extended to a larger register.

movsx eax, al
Memory trick: MOVZX → zero-fill. MOVSX → sign-preserve.

12 · Flags

Flags are 1-bit indicators maintained by the CPU. Arithmetic and comparison instructions can change them, and conditional jumps can use them.

FlagNameBeginner interpretation
ZFZero Flag1 when the result is zero.
CFCarry FlagImportant for unsigned carry/borrow.
SFSign FlagReflects the sign bit of the result.
OFOverflow FlagImportant for signed overflow.

ZF example

mov eax, 10
sub eax, 10

The result is zero, so:

ZF = 1

Unsigned vs signed overflow

CF

Think mainly about unsigned carry/borrow.

OF

Think mainly about signed overflow.

12 · CMP and TEST

CMP

CMP destination, source conceptually performs:

destination - source

but does not store the subtraction result. It changes flags.

mov eax, 10
cmp eax, 10

Conceptually:

10 - 10 = 0
ZF = 1
EAX remains 10

TEST

test eax, eax

Conceptually performs a bitwise AND without storing the result. It is commonly used to check whether a value is zero or to inspect bits.

Core conditional pattern:
cmp eax, ebx → set flags based on the comparison → conditional jump reads those flags.

14 · Jumps and Conditional Processing

Unconditional JMP

jmp label

Always transfers execution to label.

mov eax, 10
jmp skip
mov eax, 50       ; skipped

skip:

Labels

start:
    inc eax

A label marks a location in code that a jump can target.

Conditional jumps

UnsignedSignedMeaning
JEJEEqual
JNEJNENot equal
JAJGAbove / greater
JAEJGEAbove or equal / greater or equal
JBJLBelow / less
JBEJLEBelow or equal / less or equal
Important: JA/JB/JAE/JBE are for unsigned comparisons. JG/JL/JGE/JLE are for signed comparisons. JE/JNE work for equality/inequality.

IF statement

C++:

if (eax == ebx)
{
    // code
}

Assembly:

cmp eax, ebx
je equal

equal:
    ; code

IF-ELSE

cmp eax, ebx
je equal

; ELSE code
jmp done

equal:
    ; IF code

done:

Greater of two numbers

mov eax, 20
mov ebx, 30

cmp eax, ebx
jg eaxGreater

mov eax, ebx

eaxGreater:

After this, EAX contains the greater value for the signed comparison shown.

Positive / negative / zero

cmp eax, 0
jg positive
jl negative
je zero

Even / odd trick

test eax, 1
jz even

If the least significant bit is 0, the number is even. If it is 1, the number is odd.

15 · Loops

LOOP instruction

LOOP label automatically uses ECX:

ECX = ECX - 1
if ECX != 0
    jump to label

Basic pattern:

mov ecx, 5

L1:
    ; body
    loop L1

The body executes 5 times.

Print 1 to 5

mov ecx, 5
mov eax, 1

L1:
    call WriteInt
    call Crlf

    inc eax
    loop L1

Trace

IterationPrinted EAXECX after LOOP
114
223
332
441
550 → stop
LOOP trap: Do not accidentally overwrite ECX inside the loop. LOOP depends on ECX.

Loop using CMP + JMP

mov eax, 1

L1:
    cmp eax, 5
    jg done

    call WriteInt
    call Crlf

    inc eax
    jmp L1

done:

WHILE pattern

L1:
    cmp eax, 5
    jge done

    inc eax
    jmp L1

done:

Condition is checked before the body.

DO-WHILE pattern

L1:
    inc eax
    cmp eax, 5
    jl L1

The body executes once before the condition is checked.

17 · Indirect Addressing

Indirect addressing means a register contains a memory address and you access the value at that address.

Three expressions to distinguish

.data
num DWORD 50

mov esi, OFFSET num
mov eax, num
mov eax, [esi]
CodeMeaning
mov esi, OFFSET numESI gets the address of num.
mov eax, numEAX gets the value stored in num.
mov eax, [esi]EAX gets the value stored at the memory address contained in ESI.
Best mental model: ESI is a finger pointing at memory. [ESI] means “give me what the finger is pointing at.”

Traversing an array with a pointer

mov esi, OFFSET arr
mov ecx, LENGTHOF arr

L1:
    mov eax, [esi]

    ; use EAX

    add esi, TYPE arr
    loop L1

For a DWORD array, TYPE arr is 4, so ESI advances by one element each iteration.

24 · Quick Practice

Try these without looking back at the examples.

1. What are the final values of EAX and EBX? 
mov eax, 10
mov ebx, 20
xchg eax, ebx
add eax, 5
sub ebx, 3

Answer: EAX = 25, EBX = 7.

2. What does OFFSET do?

Answer: It gives the memory address of the specified variable/label. Example: mov esi, OFFSET arr makes ESI point to the first element.

3. What is the difference between mov eax, num and mov eax, [esi]?

mov eax, num reads the value of the memory variable named num. mov eax, [esi] reads the value at the memory address stored in ESI.

4. If arr is DWORD with 5 elements, what are TYPE, LENGTHOF and SIZEOF?

TYPE = 4, LENGTHOF = 5, SIZEOF = 20.

5. What does LOOP use automatically?

ECX. LOOP decrements ECX and jumps back if ECX is not zero.

6. What does cmp eax, ebx actually do?

It conceptually computes EAX - EBX to set flags, but does not store the subtraction result in EAX or EBX.

7. Which jump means signed greater-than?

JG. Unsigned greater-than is JA.

8. Write the basic array traversal pattern. 
mov esi, OFFSET arr
mov ecx, LENGTHOF arr

L1:
    mov eax, [esi]
    ; process eax
    add esi, TYPE arr
    loop L1
9. How do you check if an integer is even? 
test eax, 1
jz even

If the lowest bit is 0, the number is even.

10. Why should you be careful with ECX inside LOOP?

Because LOOP uses ECX as its counter. Overwriting ECX inside the loop changes the number of iterations and can break the loop.

24 · Lab 05 Manual Additions — Data-Related Operators, Directives & Addressing

The uploaded Fall 2026 Lab 05 manual adds several details that are easy to miss: direct-offset addressing, the exact behavior of LENGTHOF, little-endian storage, PTR, indirect operands, and indexed operands with TYPE as a scale factor.

24.1 Direct-offset operands

A direct-offset operand accesses a variable/array using its label plus a constant byte displacement.

arrayB BYTE 10h, 20h, 30h, 40h
arrayW WORD 100h, 200h, 300h

mov al, arrayB          ; element 0
mov al, [arrayB + 1]    ; element 1
mov ax, [arrayW + 2]    ; element 1
Critical: The displacement is measured in bytes, not elements. For a WORD array, the second element is at +2; for a DWORD array, the second element is at +4.
Array typeElement n addressExample for element 2
BYTE[array + n][array + 2]
WORD[array + n*2][array + 4]
DWORD[array + n*4][array + 8]

MASM does not perform array-bound checking. An invalid displacement can still assemble and may read unrelated memory.

24.2 OFFSET

mov esi, OFFSET variable

OFFSET is evaluated by the assembler and gives the address of the variable. The actual absolute address printed by a program can differ between runs/machines; the relative distances between consecutive variables depend on their sizes.

24.3 PTR — temporarily override the access size

.data
myDouble DWORD 12345678h

.code
mov ax, WORD PTR myDouble
mov al, BYTE PTR myDouble

Without PTR, mov ax, myDouble is a size mismatch because myDouble is a DWORD while AX is a WORD.

Little-endian reminder: x86 stores the least-significant byte at the lowest address. For 12345678h the bytes in memory are 78 56 34 12. Therefore WORD PTR myDouble reads 5678h, while WORD PTR [myDouble+2] reads 1234h.

24.4 TYPE, LENGTHOF and SIZEOF — exact manual behavior

OperatorReturnsExample
TYPE xBytes in one elementBYTE=1, WORD=2, DWORD=4, QWORD=8
LENGTHOF xNumber of elements in the declarationDWORD 1,2,3,4 → 4
SIZEOF xTotal bytes4 DWORDs → 16
byte1  BYTE  10,20,30                 ; TYPE=1, LENGTHOF=3, SIZEOF=3
array1 WORD  30 DUP(?),0,0            ; TYPE=2, LENGTHOF=32, SIZEOF=64
array2 WORD  5 DUP(3 DUP(?))           ; TYPE=2, LENGTHOF=15, SIZEOF=30
array3 DWORD 1,2,3,4                   ; TYPE=4, LENGTHOF=4, SIZEOF=16
digitStr BYTE "12345678",0             ; TYPE=1, LENGTHOF=9, SIZEOF=9
Formula: SIZEOF = LENGTHOF × TYPE.

LENGTHOF pitfall: it counts the values belonging to the same logical declaration statement. If a declaration is continued, it can remain part of the same declaration; starting a separate data-definition statement can change what LENGTHOF reports.

24.5 Indirect operands

mov esi, OFFSET byteVal
mov al, [esi]       ; read memory at address in ESI
mov [esi], bl       ; write to memory at address in ESI

Any 32-bit general-purpose register can serve as an indirect pointer in 32-bit mode. The brackets mean memory at the address.

ExpressionThink
ESIThe address itself
[ESI]The data stored at that address
OFFSET xThe address of x

24.6 PTR with indirect addressing

inc [esi]                 ; ERROR: size is ambiguous
inc BYTE PTR [esi]       ; 1 byte
inc WORD PTR [esi]       ; 2 bytes
inc DWORD PTR [esi]      ; 4 bytes

If another operand already determines the size, PTR is often unnecessary:

mov al, [esi]             ; AL tells MASM it is a byte
mov eax, [esi]            ; EAX tells MASM it is a DWORD

24.7 Traversing arrays with a pointer

mov esi, OFFSET arrayW
mov ax, [esi]
add esi, TYPE arrayW
mov ax, [esi]
ArrayAdvance pointer by
BYTEinc esi or add esi,1
WORDadd esi, TYPE arrayW → 2 bytes
DWORDadd esi, TYPE arrayD → 4 bytes

24.8 Indexed operands

The manual introduces the very useful pattern:

arrayName[indexRegister * TYPE arrayName]

This lets the index register represent an element number rather than a byte offset.

.data
arrayW WORD 1000h,2000h,3000h,4000h
arrayD DWORD 11111111h,22222222h,33333333h

.code
mov esi, 1
mov ax, arrayW[esi * TYPE arrayW]       ; 2000h
mov esi, 2
mov eax, arrayD[esi * TYPE arrayD]      ; 33333333h
Exam trick: If the question says “element/index 3,” first ask whether the expression expects a byte displacement or an element index. array[3] is not automatically “fourth element” in every addressing form; the scale factor matters.

24.9 Lab 05 patterns to practice

  2. Calculate TYPE, LENGTHOF and SIZEOF without running the program.
  3. Predict the result of BYTE PTR / WORD PTR / DWORD PTR accesses.
  4. Trace ESI while traversing an array with add esi, TYPE array.
  5. Trace indexed expressions such as array[esi * TYPE array].

25 · Lab 06 Manual Additions — Arrays, JMP, LOOP & Irvine32

The uploaded Lab 06 manual is broader than just “arrays + loops.” It explicitly covers unconditional control transfer, fixed-count LOOPs, nested loops, console I/O, screen/colour control, memory display, random numbers and message boxes.

25.1 Arrays in the Lab 06 manual

marks   BYTE   78,85,62,91,70
years   WORD   2022,2023,2024,2025
prices  DWORD  1500,2750,3200
buffer  BYTE   50 DUP(?)
city    BYTE   "Karachi",0

Remember: an array is consecutive memory containing elements of the same declared type. A string is effectively a BYTE array containing character codes and, when null-terminated, a final zero byte.

25.2 Transfer of control

Normally execution is sequential. A transfer of control changes where EIP continues execution.

TypeMeaningExamples in this lab
UnconditionalAlways transfer controlJMP
ConditionalTransfer only when a condition/flags permit itJE, JNE, JG, JL, etc.
Important scope clarification: The Lab 06 manual specifically says this lab focuses on unconditional JMP and LOOP; conditional jumps, CMP and flags are studied in a future lab. Keep the conditional-jump material in this sheet as useful background, but prioritize JMP/LOOP for a Lab 1–6 exam unless your instructor explicitly included later material.

25.3 Labels

Skip:
    mov eax, 10

A label names a code location; it does not reserve data storage.

25.4 JMP — forward and backward

jmp Skip

; skipped instructions

Skip:
    ; execution continues here

Forward JMP: usually skips a block. Backward JMP: returns to earlier code and can create repetition.

Top:
    inc eax
    call WriteDec
    call Crlf
    jmp Top

This is an endless loop because JMP itself never checks a stopping condition.

25.5 PUSH / POP in the Lab 06 context

push eax
mov eax, 500
call Delay
pop eax

PUSH saves a register value on the stack; POP restores it. The manual uses this pattern when EAX must temporarily hold a procedure argument while the original counter/value needs to survive.

25.6 LOOP — exact behavior

mov ecx, 5
L1:
    ; body
    loop L1

In 32-bit mode, LOOP always uses ECX:

ECX = ECX - 1
if ECX != 0 → jump to label
else → continue after LOOP
LOOP does not modify flags. Also, ECX must not be unintentionally changed inside the loop.

Important LOOP mistakes from the manual

  • ECX = 0 before LOOP: LOOP decrements it first, producing FFFFFFFFh, so the loop can run 4,294,967,296 times. Always start with a non-zero count.
  • Changing ECX inside the body: this corrupts the loop counter. Save/restore it if a nested loop or procedure requires ECX.
  • Very long LOOP body: LOOP's encoded destination has a short displacement range; an excessively distant label can produce a “jump destination too far” assembler error.

25.7 Counting and summation pattern

mov ebx, 0
mov ecx, 10

L1:
    add ebx, ecx
    mov eax, ecx
    call WriteDec
    loop L1

; EBX = 55

ECX values used by the body are 10, 9, 8, ..., 1. Therefore the sum is 55.

25.8 Array sum using indexed addressing

intArray DWORD 10,20,30,40,50

mov esi, 0
mov ebx, 0
mov ecx, LENGTHOF intArray

L1:
    mov eax, intArray[esi * TYPE intArray]
    add ebx, eax
    inc esi
    loop L1

At the end, EBX = 150.

25.9 Filling an array with a loop

multiples DWORD 8 DUP(?)

mov esi, OFFSET multiples
mov eax, 0
mov ecx, LENGTHOF multiples

Fill:
    add eax, 5
    mov [esi], eax
    add esi, TYPE multiples
    loop Fill

This creates 5, 10, 15, 20, 25, 30, 35, 40.

25.10 Nested loops

Because LOOP always uses ECX, an inner loop would destroy the outer loop counter unless you save and restore it.

.data
outerCount DWORD ?

.code
mov ebx, 1
mov ecx, 5

Outer:
    mov outerCount, ecx
    mov ecx, ebx

Inner:
    mov al, '*'
    call WriteChar
    loop Inner

    call Crlf
    inc ebx
    mov ecx, outerCount
    loop Outer

Output:

*
**
***
****
*****
Nested-loop rule: save outer ECX → load inner ECX → run inner LOOP → restore outer ECX → run outer LOOP.

25.12 Output formats — an easy exam comparison

mov eax, 2026
call WriteDec    ; 2026
call WriteInt    ; +2026
call WriteHex    ; 000007EA
call WriteBin    ; binary representation

mov al, 'A'
call WriteChar   ; A

For a negative value such as -2026, WriteInt displays the signed value, while WriteHex shows its 32-bit two's-complement bit pattern.

25.13 ReadString pattern

userName BYTE 31 DUP(0)

mov edx, OFFSET userName
mov ecx, SIZEOF userName
call ReadString

EDX points to the buffer, ECX gives the buffer size, and EAX returns the number of characters read. The procedure stores a null terminator, allowing the buffer to be printed using WriteString.

25.14 Screen and colour procedures

call Clrscr

mov eax, yellow + (blue * 16)
call SetTextColor

mov dh, 3
mov dl, 10
call Gotoxy

mov edx, OFFSET msg
call WriteString

Rows and columns start at 0. The colour value is:

foreground + (background * 16)

Manual colour constants include black=0, blue=1, green=2, cyan=3, red=4, magenta=5, brown=6, lightGray=7, gray=8, lightBlue=9, lightGreen=10, lightCyan=11, lightRed=12, lightMagenta=13, yellow=14, white=15.

25.15 DumpMem

mov esi, OFFSET arrayW
mov ecx, LENGTHOF arrayW
mov ebx, TYPE arrayW
call DumpMem

This is a very useful debugging technique: OFFSET gives the start address, LENGTHOF gives the number of units, and TYPE gives the unit size.

25.16 Random numbers

call Randomize
mov eax, 6
call RandomRange       ; EAX = 0..5
inc eax                ; EAX = 1..6

The manual's dice example fills an array with 10 random values from 1 to 6:

rolls DWORD 10 DUP(?)

call Randomize
mov esi, OFFSET rolls
mov ecx, LENGTHOF rolls

Fill:
    mov eax, 6
    call RandomRange
    inc eax
    mov [esi], eax
    add esi, TYPE rolls
    loop Fill
Call Randomize once near the beginning. RandomRange with EAX=n returns values from 0 through n−1.

25.17 Message boxes

cap BYTE "Lab 06",0
msg BYTE "Assembly language is fun!",0

mov ebx, OFFSET cap
mov edx, OFFSET msg
call MsgBox

For MsgBoxAsk, EDX is the message, EBX is the caption, and EAX receives IDYES = 6 or IDNO = 7.

mov ebx, OFFSET cap
mov edx, OFFSET question
call MsgBoxAsk
; EAX = 6 for Yes, 7 for No

Multi-line message text can contain 0Dh,0Ah between lines.

Last-minute dry-run checklist

  1. Underline every register that changes.
  2. Circle every memory access and ask: value or address?
  3. For an array, write the element size beside it.
  4. For LENGTHOF, count elements—not bytes.
  5. For SIZEOF, multiply element count × element size.
  6. For [array + displacement], remember displacement is bytes.
  7. For array[index * TYPE array], treat index as an element number.
  8. For LOOP, write the ECX value before and after every iteration.
  9. For nested LOOPs, mark where outer ECX is saved and restored.
  10. For Irvine32 calls, check the required input register immediately before CALL.

Final Mental Model

When you see Assembly code, read it as a sequence of very small actions:

1. Where is the data?
        ↓
2. Which register holds it?
        ↓
3. Is this a value or an address?
        ↓
4. If [register] appears, what memory does it point to?
        ↓
5. If CMP appears, which flags change?
        ↓
6. Which jump reads those flags?
        ↓
7. If LOOP appears, what is ECX?
        ↓
8. If it is an array, how far should the pointer move?
        ↓
9. Dry-run the values one instruction at a time.
Do not memorize Assembly as random syntax. Build the mental model first. Once you understand what the registers, memory addresses, flags and jumps are doing, the code becomes much easier to predict and write.
